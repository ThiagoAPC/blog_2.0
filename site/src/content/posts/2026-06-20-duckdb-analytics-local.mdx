DuckDB é provavelmente a ferramenta mais subestimada no toolkit de um engenheiro de dados.
É um banco de dados analítico *in-process* — sem servidor, sem configuração, sem cluster —
que roda direto no seu laptop e processa centenas de gigabytes em segundos.

## Por que DuckDB é Revolucionário

A maioria das ferramentas analíticas exige infraestrutura:


```python
import duckdb

# Conexão in-memory (dados somem ao fechar)

# Ou persistida em arquivo

```

  DuckDB lê arquivos Parquet, CSV, JSON e Arrow diretamente. Você não precisa "importar"
  os dados — ele consulta os arquivos como se fossem tabelas.

## Lendo Parquet Direto do S3

Uma das features mais poderosas: queries em arquivos remotos sem ETL prévio.

```python
import duckdb

conn = duckdb.connect()

# Instalar e carregar extensão httpfs (S3, GCS, Azure)
conn.execute("INSTALL httpfs; LOAD httpfs;")
conn.execute("""
    SET s3_region = 'us-east-1';
    SET s3_access_key_id = 'YOUR_KEY';
    SET s3_secret_access_key = 'YOUR_SECRET';
""")

# Query direta em arquivos Parquet particionados no S3
result = conn.execute("""
    SELECT
        DATE_TRUNC('month', event_date)   AS mes,
        event_type,
        COUNT(*)                           AS total_eventos,
        COUNT(DISTINCT user_id)            AS usuarios_unicos,
        AVG(session_duration_seconds)      AS duracao_media_seg
    FROM read_parquet(
        's3://meu-datalake/events/year=2026/month=*/day=*/*.parquet',
        hive_partitioning = true
    )
    WHERE event_date >= '2026-01-01'
      AND event_type IN ('purchase', 'add_to_cart', 'view_product')
    GROUP BY 1, 2
    ORDER BY 1 DESC, 3 DESC
""").df()  # Retorna Pandas DataFrame

print(result.to_string(index=False))
```

## Benchmark: DuckDB vs Pandas vs Spark

Para ilustrar a diferença de performance em dados de ~1GB:

| Operação                    | Pandas     | DuckDB    | Spark Local |
|-----------------------------|------------|-----------|-------------|
| `GROUP BY` + `COUNT`        | 8.2s       | **0.4s**  | 12.1s       |
| `JOIN` duas tabelas         | 15.7s      | **1.1s**  | 9.3s        |
| Leitura Parquet + filter    | 3.1s       | **0.2s**  | 8.7s        |
| Window functions            | 22.4s      | **1.8s**  | 7.2s        |
| Escrita Parquet             | 4.5s       | **0.9s**  | 11.2s       |

<Callout type="note" title="Metodologia">
  Benchmark em MacBook Pro M3 Max, 36GB RAM, arquivo Parquet de 1.2GB (~8M linhas).
  Spark com modo local[*]. Resultados variam conforme hardware e dados.
</Callout>

## Padrão de Exploração com DuckDB + Python

Um workflow completo de exploração de dados:

```python
import duckdb
import polars as pl
from pathlib import Path

def explorar_dataset(caminho: str | Path) -> None:
    """
    Exploração rápida de qualquer arquivo de dados.
    Funciona com .parquet, .csv, .json
    """
    conn = duckdb.connect()
    
    # 1. Visão geral do schema
    print("=== SCHEMA ===")
    conn.execute(f"DESCRIBE SELECT * FROM '{caminho}'").show()
    
    # 2. Estatísticas descritivas
    print("\n=== ESTATÍSTICAS ===")
    conn.execute(f"SUMMARIZE SELECT * FROM '{caminho}'").show()
    
    # 3. Sample dos dados
    print("\n=== AMOSTRA (5 linhas) ===")
    conn.execute(f"SELECT * FROM '{caminho}' LIMIT 5").show()
    
    # 4. Checar duplicatas na chave primária
    total = conn.execute(f"SELECT COUNT(*) FROM '{caminho}'").fetchone()[0]
    unicos = conn.execute(f"SELECT COUNT(DISTINCT *) FROM '{caminho}'").fetchone()[0]
    print(f"\nLinhas totais: {total:,} | Únicas: {unicos:,} | Duplicatas: {total - unicos:,}")
    
    # 5. Exportar para Parquet otimizado
    output = Path(caminho).with_suffix('.optimized.parquet')
    conn.execute(f"""
        COPY (
            SELECT * FROM '{caminho}'
            ORDER BY 1  -- Sort pela primeira coluna para melhor compressão
        ) TO '{output}'
        (FORMAT PARQUET, COMPRESSION ZSTD, ROW_GROUP_SIZE 100000)
    """)
    print(f"\nExportado para: {output}")

# Uso
explorar_dataset("data/orders_2026.csv")
```

## Integração com Polars

DuckDB e Polars se complementam perfeitamente:

```python
import duckdb
import polars as pl

# Polars → DuckDB (zero-copy via Apache Arrow)
df_polars = pl.read_parquet("events.parquet")

resultado = duckdb.execute("""
    SELECT
        user_id,
        SUM(revenue)    AS receita_total,
        COUNT(*)        AS num_pedidos
    FROM df_polars      -- Referencia o DataFrame Polars diretamente!
    WHERE revenue > 0
    GROUP BY user_id
    HAVING COUNT(*) >= 3
    ORDER BY receita_total DESC
    LIMIT 100
""").pl()  # Retorna Polars DataFrame diretamente

print(resultado)
```

## Quando NÃO usar DuckDB

DuckDB não é bala de prata. Ele não substitui:

- **Dados > RAM disponível** → Use Spark ou BigQuery
- **Múltiplos writers concorrentes** → Use PostgreSQL ou Iceberg + Spark
- **Streaming em tempo real** → Use Kafka + Flink
- **Dados > 500GB** → DuckDB pode lidar, mas fica lento sem otimização
